# Pantone Challenger V1.5.1 Release Report

## Release name

**Color Truth and Pixel Provenance**

## Why this release exists

A code and evidence audit found that V1.5.0 could display plausible-looking but statistically averaged HEX values that did not literally occur in the source creative. The same audit found that the color-family mapper used hue boundaries that did not align with the OKLCH wheel.

V1.5.1 makes the exact displayed color independently auditable from capture through social rendering.

## Corrective changes

- Palette clustering moved from raw RGB to perceptual OKLab.
- Every extracted swatch now uses an actual decoded source pixel nearest its cluster center.
- Every public candidate now uses a source-balanced observed medoid rather than an averaged cross-source centroid.
- Cross-source clustering uses complete linkage to prevent color drift through chains of neighboring shades.
- Transparent pixels are excluded instead of being composited onto beige.
- Border-connected neutral infrastructure is flagged and removed from candidate voting while remaining available for palette-regime analysis.
- Connected-area and spatial-coverage measurements reduce the influence of scattered text, icons, and interface accents.
- OKLCH color-family boundaries were recalibrated against canonical sRGB anchors.
- A private `color-proof-sheet.png` shows the source crop beside a masked view of the actual matching pixels.
- A private `color-truth-audit.json` independently reopens every evidence image and verifies exact pixel membership.
- A public `color-integrity.json` records the number of images, swatches, candidates, and evidence records checked.
- A failed color-provenance audit is a hard software failure: no social asset is rendered or published.
- The historical baseline compatibility key changed so older synthetic centroids cannot influence V1.5.1 emergence scoring.
- Browser capture now waits for lazy imagery to decode and correctly treats an image element itself as visual content.

## Evidence audit

The old and new extractors were run against the same 60 creative-region images from the September 5 private evidence artifact.

| Version | Extracted swatches | Swatches absent from source pixels | Rate |
|---|---:|---:|---:|
| V1.5.0 | 393 | 204 | 51.91% |
| V1.5.1 | 406 | 0 | 0.00% |

The V1.5.1 audit was rerun using four worker processes and exact decoded RGB membership checks. All 406 generated swatches were found in the source images.

## Validation completed

- 46 automated tests passed.
- Python compilation passed.
- Release validation passed with zero errors.
- 67 enabled sources were validated.
- 12 cultural domains, all three signal stages, 40 benchmark sources, and 27 discovery sources were present.
- Feed and runner-up rendering tests confirmed exact swatch RGB values.
- Runtime provenance tests confirmed that fabricated absent HEX values are rejected.

## Remaining limitation

Pixel provenance proves that a HEX value occurred in a decoded evidence image. It does not prove that the captured region was culturally meaningful, current, or free of every possible interface artifact. Creative-region selection, overlay rejection, duplicate reduction, source balancing, baseline comparison, emergence gates, and human calibration review remain necessary.

The first live V1.5.1 run should therefore remain an internal calibration run and its private proof sheet should be reviewed before any social publication.
